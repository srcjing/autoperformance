# auto_performance 个人数据说明

**产品**：auto_performance（性能测试平台）　**版本**：v1.0　**日期**：2026-10-26
**适用范围**：本产品在客户内网离线部署后的个人数据处理说明（隐私声明/数据处理清单）
**依据**：`security/security-design-report.md`（DES-I-004 PII 最小化）、`backend/migrations/000001_init_schema.up.sql`、`backend/internal/api/setting/admin.go`
*本文档与实现同步；处理范围发生变化时必须先更新本文档再发布。*

---

## 1. 处理者与部署位置

- 本产品为**客户自建、内网离线部署**的软件，不提供 SaaS 服务。
- 数据控制者为部署方（客户）；产品不向任何第三方回传数据，**无数据出境**（无互联网出站、无遥测）。
- 部署形态：单机 systemd 或单主机 Docker；数据仅保存在部署主机（PostgreSQL + 本地报告目录）。

## 3. 处理目的与合法性基础

| 目的 | 说明 |
|------|------|
| 身份认证与账号管理 | 登录、改密、停用、角色授权 |
| 分级分权访问控制 | 按子模块 read/write 授权，最小权限 |
| 安全审计与追溯 | 记录操作人/时间/IP/动作/资源/结果，满足《网络安全法》审计留存要求 |
| 性能测试业务执行 | 任务归属、报告归属、问题定位 |

处理基于部署方作为数据控制者的内部管理需要与法定义务（审计留存）；不用于营销、画像、自动化决策。

---

## 4. 最小化与访问控制

1. **字段最小化**：手机号/邮箱/描述为可选字段；内置 admin 不预置任何 PII；新建账号请求体仅接受白名单字段。
2. **访问控制（服务端强制）**：
   - 管理员信息（含 PII）仅在 `setting.admin:write` 授权下可读写（敏感子模块 write-only）；
   - 操作日志按 `log.user` / `log.system` / `log.test` 的 `read` 权限隔离；
   - 环境主机地址仅对具备 `env.list:read` 的管理员返回，无权限时响应体不含 `hosts`。
3. **展示最小化**：接口响应不含口令哈希；接口认证头只返回“名称”，不返回值；报告内容剥离查询串与认证头。
4. **日志脱敏**：所有日志/WS 推送写入前统一剥离 `Authorization`、`password=`、私钥块。

## 5. 存储、传输与安全措施

| 环节 | 措施 |
|------|------|
| 传输 | 生产要求 TLS ≥1.2（反向代理终止），禁止明文跨网传输；WS 同源同端口 |
| 存储（口令） | bcrypt cost=10 哈希 + 随机盐，不可逆 |
| 存储（凭据/私钥） | 接口认证头、证书私钥、SSH 私钥：AES-256-GCM + KEK 信封加密 |
| 存储（审计） | HMAC-SHA256 链式签名 + DB 触发器禁止 UPDATE/DELETE |
| 存储（文件） | 报告目录 0750、产物 0640；上传随机文件名，不使用原文件名 |
| 备份 | 由部署方按备份策略加密保管；备份介质适用同等保护级别 |
| 运维访问 | 数据库仅本机/容器网络；低权限 DB 账号；服务进程非 root |

## 6. 保存期限与删除

1. **账号数据**：账号存续期内保存；删除为**逻辑删除**（`deleted_at`），保留历史审计关联。
2. **审计日志**：按 `created_at` 季度分区保存，**应用不提供删除/修改接口**（防篡改红线）；到期后由运维按合规保留策略
   导出归档并 `DROP PARTITION` 清除。建议保留期 ≥6 个月（按部署方合规要求确定）。
3. **任务/报告**：随业务数据保留；可删除时删除记录与产物文件（逻辑删除 + 文件清理由运维执行）。
4. **卸载**：`uninstall.sh` 默认保留数据；`--purge-data` 需输入 `YES` 二次确认后物理删除。

## 7. 数据主体权利

| 权利 | 实现方式 |
|------|----------|
| 知情 | 本文档 + 部署方内部告知 |
| 访问/更正 | 管理员可通过「系统设置 → 管理员管理」查看/修改姓名、手机号、邮箱、描述（`PUT /admins/{id}`） |
| 删除 | 管理员可逻辑删除账号（`DELETE /admins/{id}`）；内置 admin 不可删除。审计日志因法定义务/防篡改要求不做删除，仅在保留期后按分区清除 |
| 撤回/限制处理 | 停用账号（`PATCH /admins/{id}/status`）+ 解除角色绑定，立即失去访问能力 |
| 解释 | 审计日志可查询操作人与动作，用于说明处理过程 |

> 例外说明：审计日志的不可篡改与不可删除是安全红线要求（DES-T-006）。如数据主体要求删除，应通过“停用账号 + 保留期后分区清除”处理，并在合规记录中说明。

## 8. 共享、委托处理与出境

- **不共享**：产品不与任何第三方系统对接、不外发数据、无 SDK/埋点/遥测。
- **不委托处理**：无云服务、无外部日志/监控平台（部署方自行接入的集中日志属其自主行为）。
- **不出境**：离线内网部署，运行期无互联网出站；数据本地留存。

---

## 9. 安全事件响应

1. 发现异常登录/越权 → 停用账号、重置口令（旧 token 立即失效）、检查审计链完整性。
2. 怀疑数据泄露 → 保留现场（审计日志只读）、评估影响范围（按 `admin_id`/`ip` 检索）、按部署方应急预案上报。
3. 审计链校验：篡改任一条日志会导致 `hash` 校验失败（应用侧 `VerifyAuditChain` + DB 触发器兜底）。
