# auto_performance 通信矩阵

**产品**：auto_performance（性能测试平台）　**版本**：v1.0　**日期**：2026-10-26
**适用形态**：离线单机（systemd + 内嵌前端）、容器编排（docker compose）、前后端分离联调
**依据**：`security/security-design-report.md`（DES-S-001 / DES-I-001 / TEST-S-001 / TEST-I-001）、`deploy/` 实际脚本与配置
*本文件与实现同步维护；端口/方向变更必须先更新本矩阵再改部署脚本。*

---

## 1. 部署形态与信任边界

| 形态 | 入口 | 后端监听 | 数据库 | 信任边界 |
|------|------|----------|--------|----------|
| 离线单机（推荐生产） | 运维反向代理（可选 TLS）→ `127.0.0.1:8080` | `server.host/port`（`install.sh` 默认 `0.0.0.0:8080`，**须收敛**，见 §5） | 随包 PostgreSQL，`listen_addresses=127.0.0.1` + Unix socket | 单机，全部组件同主机 |
| 容器编排 | `frontend(nginx) :8088 → 80` | `backend` 容器 `:8080`，宿主机仅绑定 `127.0.0.1:8080` | `postgres` 容器 `:5432`，**不发布端口** | 单主机 Docker 网络 |
| 前后端分离联调 | `vite dev :5173`（`/api` 代理到 `127.0.0.1:8080`） | `127.0.0.1:8080` | 开发机 PostgreSQL | 仅开发环境，禁止用于生产 |

单二进制内嵌前端（`go:embed web/dist`）：非 `/api`、`/healthz` 路径由后端直接返回 `index.html` 与静态资源，
**不需要额外静态服务器**；容器形态的 nginx 仅作为可选入口与反向代理。

## 2. 入站通信（Inbound）

| 序号 | 源 | 目标 | 协议/端口 | 用途 | 鉴权 | 备注 |
|------|----|------|-----------|------|------|------|
| IN-1 | 管理员浏览器 / API 客户端 | 反向代理或后端 | HTTPS/HTTP **8080**（容器入口 8088→80） | REST API `/api/v1/*`、健康检查 `/healthz` | JWT（`Authorization: Bearer`）+ RBAC | 生产必须经 TLS 反代；不得直接暴露公网（DES-I-001） |
| IN-2 | 管理员浏览器 | 同上 | WSS/WS **同 8080**，路径 `/api/v1/ws?token=<jwt>` | 任务状态/指标/实时日志推送 | 握手 token 校验（账号状态 + 首登改密 + 权限） | token 走 query（浏览器 WS 无法自定义头），须经 TLS |
| IN-3 | 运维/监控 | 后端 | HTTP **8080** `/healthz` | 存活/就绪探测（含 DB 连通性） | 无（只返回 `status`/`db`） | 建议仅本机或监控网段可达 |
| IN-4 | 本机运维 | PostgreSQL | TCP **127.0.0.1:5432** + Unix socket | 数据库管理/备份 | 数据库账号口令 | 离线形态仅监听回环；容器形态不发布端口 |

> 入站仅上述端口。未开放：SSH 服务端、k6 服务、Chromium 调试端口、任何管理 API 的独立端口。

## 3. 出站通信（Outbound）

| 序号 | 源 | 目标 | 协议/端口 | 用途 | 安全控制 |
|------|----|------|-----------|------|----------|
| OUT-1 | backend | PostgreSQL | TCP **5432**（本机回环 / 容器网络 / 外部实例） | 业务数据、审计日志、迁移 | 低权限 DB 账号（NOSUPERUSER）、`sslmode` 可配（跨主机必须 `require`+） |
| OUT-2 | backend → k6 子进程 | 被测系统 | HTTP/HTTPS（**80/443 或被测端口**） | 接口压测流量 | k6 以参数数组启动（无 shell）、并发/时长白名单、URL 白名单校验；子进程低权限账号 |
| OUT-3 | backend（cleaner） | 清理目标主机（SSH/Host） | SSH **22**（可在 SSH/Host 记录中配置端口） | 恢复配置/清理数据/重启服务/受控脚本 | 主机白名单 + 脚本 SHA256 白名单 + **严格主机公钥校验**（`ssh.FixedHostKey`，禁用 `InsecureIgnoreHostKey`） |
| OUT-4 | backend | 本地 Chromium 子进程 | 本机进程，无监听端口 | HTML → PDF 打印 | 超时中断（`report.gen_timeout_seconds`）、参数数组、无 shell |
| OUT-5 | backend | 本地文件系统 | — | 报告产物、k6 脚本/结果、KEK | 报告目录 0750/产物 0640、脚本 0600 且执行后删除、KEK 0600 |

**无互联网出站**：产品运行期不访问公网、无遥测/升级回连、无第三方 SaaS 依赖（离线交付）。
打包机侧的依赖下载不属于运行期通信。

## 4. 数据流与保护

| 数据 | 路径 | 传输保护 | 存储保护 |
|------|------|----------|----------|
| 登录口令 | 浏览器 → 后端 | TLS（生产必须） | bcrypt（cost=10）哈希，不落明文；日志脱敏 |
| JWT | 后端 → 浏览器 → 后端 | TLS | 无状态；`jti` 失效名单（内存，登出/改密失效） |
| 接口认证头（Authorization/Token 等） | 浏览器 → 后端 → k6 脚本 | TLS | AES-256-GCM 密文（`interface.headers_enc`），响应仅返回头名；报告/日志不含 |
| 证书私钥 / SSH 私钥 | 上传 → 后端 → SSH 客户端 | TLS | AES-256-GCM + KEK 信封加密（KEK 0600，DEK 每对象随机） |
| 审计日志 | 后端 → PostgreSQL | 同 OUT-1 | HMAC-SHA256 链式签名 + DB 触发器禁止 UPDATE/DELETE，应用层无改删接口 |
| 报告产物（html/pdf/docx） | 后端 → 浏览器（在线查看/导出） | TLS | 目录白名单 + `filepath.Clean` 前缀校验；文件名由服务端生成；不存认证头 |
| 环境主机地址（内网拓扑） | 后端 → 浏览器 | TLS | 仅 `env.list:read` 可见；无权限时响应不含 `hosts` |

## 5. 端口收敛与核查

### 5.1 上线前必须确认

1. **后端监听地址**：离线形态 `install.sh` 渲染 `host: "0.0.0.0"`（便于接入反代）。若主机直接可达业务网，
   必须改为 `127.0.0.1`（或由防火墙限制仅反代/管理网段访问），否则不满足「管理面不绑定 0.0.0.0」（DES-I-001 / TEST-I-001）。
2. **数据库端口**：随包 PostgreSQL 已配置 `listen_addresses=127.0.0.1`；不得改为 `*` 或 `0.0.0.0`。
3. **TLS**：生产必须在反向代理终止 TLS（TLS ≥ 1.2，禁用 RC4/3DES/MD5），后端只监听回环。
4. **防火墙**：仅放行入口端口（8080 或反代 443）与必需出站（被测系统、SSH 目标机）。

### 5.2 核查命令（真机执行，人工留存输出）

```bash
# 1) 侦听端口清单（比对本矩阵）
ss -tlnp
# 2) 全端口扫描（从同网段另一台机器执行）
nmap -sS -sV -p 1-65535 <host>
# 3) 确认侦听进程身份（非 root）
ss -tlnp | grep 8080
ps -o user=,pid=,cmd= -p <pid>
# 4) 确认数据库未对外
ss -tlnp | grep 5432        # 期望仅 127.0.0.1:5432 或 Unix socket
# 5) 确认无未公开公网地址
strings /opt/auto_performance/bin/auto_performance | grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' | sort -u
```

**判定标准**：`ss`/`nmap` 结果中所有侦听端口必须在本矩阵 IN-1~IN-4 内；无未记录的动态端口；
后端/数据库进程属主非 `root`；`strings` 输出不含未公开公网 IP/域名。

### 5.3 变更流程

新增端口/外联目标 → 先更新本矩阵（含用途、鉴权、控制措施）→ 安全评审 → 修改部署脚本 → 用 §5.2 命令复核。
