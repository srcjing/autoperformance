# auto_performance 安全加固指南

**产品**：auto_performance（性能测试平台）　**版本**：v1.0　**日期**：2026-10-26
**适用对象**：部署/运维/安全评审人员　**依据**：`security/security-design-report.md`、`deploy/` 脚本与 `backend/internal/config/config.go`
*本指南只描述已实现的控制点与必须由部署侧完成的动作；标注「残留风险」的项需按建议处置。*

---

## 1. 进程与账号

| 项 | 已实现 | 加固动作 |
|----|--------|----------|
| 服务身份 | systemd 单元 `User=autoperf`、`NoNewPrivileges=true`、`ProtectSystem=strict`；容器镜像非 root（USER 10001）、`cap_drop: ALL`、`read_only` rootfs | 确认 `systemctl cat auto_performance` 中 `User` 非 root；禁止用 root 手工启动二进制 |
| 低权限子进程 | k6 子进程按 `cleaner.low_priv_uid/gid` 降权（Unix）；未配置则保持当前身份 | 生产必须配置为专用无登录账号（如 65534/nobody 或自建 `autoperf-exec`） |
| 文件系统 | 配置 `0640`、KEK `0600`、数据目录 `0750`、报告产物 `0640`、k6 脚本 `0600` 且执行后删除 | 校验 `ls -l` 权限与属主；不要把数据目录放到全局可读位置 |
| Shell | k6/Chromium 均以参数数组启动，无 shell 解释器；SSH 只执行内置受控动作 | 禁止在配置中拼接命令行字符串，禁止自定义脚本绕开白名单 |

```bash
# 核查（真机）
ps -o user=,pid=,cmd= -p $(pgrep -f 'bin/auto_performance' | head -1)   # 期望 autoperf
ls -l /var/lib/auto_performance/keys/kek.key                            # 期望 -rw------- autoperf
ls -ld /var/lib/auto_performance/reports                                # 期望 drwxr-x--- autoperf
```

## 2. 密钥与凭据

| 密钥 | 生成方式 | 存放/权限 | 轮换 |
|------|----------|-----------|------|
| JWT 签名密钥 `jwt.secret` | `install.sh` 生成 32 字节随机 hex | `config.yaml`（0640 root:autoperf）或环境变量 `AUTO_PERF_JWT_SECRET` | 可轮换：替换后所有已签发 token 立即失效（用户需重新登录） |
| KEK（信封根密钥） `security.kek_path` | `install.sh` 生成 32 字节（hex 写入），`gen_hex 32` | `keys/kek.key`，**0600**，属主 autoperf；目录 0700 | **不可直接替换**（历史密文将不可解）。轮换流程：解密旧密文 → 用新 KEK 重新加密 → 原子替换 KEK |
| 审计链 HMAC `security.audit_hmac_key` | 安装脚本生成或环境变量注入 | 建议经 `AUTO_PERF_SECURITY_AUDIT_HMAC_KEY` 注入，不落盘 | 轮换会使历史链校验断点；仅在新周期开始时轮换并归档旧密钥 |
| 应用额外秘密 `security.secret_key_env` | 安装脚本生成 `keys/secret.env`（0600） | 环境变量 `AUTO_PERF_SECRET_KEY` | 同上 |
| 数据库口令 | `--db-password` 指定或安装时随机 16 字节 | `config.yaml`（0640） | 通过 `ALTER ROLE … PASSWORD`（安装脚本以 psql 变量传参，无拼接） |
| 报告上传目录 | 服务端随机文件名（不使用原文件名） | `security.report_dir`（0750） | — |

**禁止**：把 KEK/口令写入镜像、命令行参数、日志、Git；`config.example.yaml` 中的开发默认值（JWT secret / DB 口令）不得用于生产。
**核查**：`grep -RnE 'password|secret|PRIVATE KEY' config.yaml` 只允许出现占位/引用；`strings` 二进制中不得出现明文初始口令（见《安全专项测试证据》）。

## 3. 网络

1. 后端只监听回环，统一由反向代理暴露（见《通信矩阵》§5）。
2. TLS ≥ 1.2，禁用 RC4/3DES/MD5；HSTS 建议在反代开启。
3. 安全响应头（容器 nginx 已内置，离线自建反代需对齐）：
   `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、
   `Content-Security-Policy default-src 'self'; …`、`Permissions-Policy`。
4. 数据库不得对外发布端口；跨主机连接必须 `sslmode=require`（或 `verify-full`）。
5. 与管理网/被测网隔离：被测系统可能因压测产生高流量，建议独立网段与限速策略。
6. **CORS 残留风险**：中间件当前返回 `Access-Control-Allow-Origin: *`（同源内嵌部署下不生效）。
   若采用前后端分离部署，必须在反向代理层删除该响应头并仅允许受信源，或在前端与后端同域部署。

## 4. 认证与会话

| 控制 | 实现 | 建议 |
|------|------|------|
| 口令存储 | bcrypt cost=10（`$2a$10$`），自动加盐 | 禁止改为 MD5/SHA1；禁止明文落库 |
| 口令策略 | ≥8 位且 ≤72 字节，含大写/小写/数字/特殊字符 | 首次登录强制修改；定期更换建议 90 天 |
| 防暴力破解 | 连续失败 5 次锁定 15 分钟，**账号 + IP 双维度**；错误提示统一（不区分账号不存在/口令错误） | 生产建议在反代叠加 IP 级限流/fail2ban |
| 会话 | JWT HS256，默认 24h（`jwt.expire_seconds=86400`），含 `jti` | 建议缩短至 2~8h；登出/改密/重置口令后旧 token 立即失效 |
| 首登改密 | `must_change_password=true` 时仅允许 `/auth/change-password`、`/auth/logout`、`/auth/me` | 不要为内置 admin 关闭该标记 |
| 权限 | 每次请求从 DB（30s TTL 缓存）加载权限并集，角色变更即时失效缓存 | 前端隐藏不替代服务端鉴权；不要直接改库授予权限 |

```bash
# 暴力破解防护验证（会触发锁定，验证后解锁等待或重启服务）
for i in $(seq 1 6); do curl -s -o /dev/null -w '%{http_code}\n' \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"wrong"}' http://127.0.0.1:8080/api/v1/auth/login; done
# 期望：前 5 次 401/20001，第 6 次 429/10502
```

## 5. 授权（分级分权 RBAC）

1. 权限点 = `module_code:read|write`，`write` 蕴含 `read`；路由级强制（`middleware.AuthZ`）。
2. **敏感子模块 write-only**：`setting.admin`、`setting.cert`、`setting.ssh` 仅授予可信运维角色；
   即使授予 `read` 也不会放开（路由要求 `write`）。
3. 新建管理员默认启用、**默认无任何角色/权限**（防 Mass Assignment：请求体中的 role/status 等字段被丢弃）。
4. 内置 `admin`（`is_builtin=true`）隐式全权限、不可删除/停用（`26002`）。
5. 被引用的角色不可删除（`26003`）；角色绑定时权限即时生效。
6. 日志子模块只读，且没有任何写/删/改路由。

**最小权限示例**：

| 角色 | 建议权限 |
|------|----------|
| 只读观察者 | `env.list:read`、`env.tag:read`、`product.list:read`、`product.interface:read`、`testing.template:read`、`testing.task:read`、`report.list:read`、`log.user:read`、`log.system:read`、`log.test:read` |
| 测试执行者 | 观察者 + `testing.task:write`、`testing.template:write`、`report.list:write` |
| 资产维护 | `env.list:*`、`env.tag:*`、`product.list:*`、`product.interface:*` |
| 平台管理员 | 全部（含 `setting.admin:*`、`setting.cert:*`、`setting.ssh:*`） |

## 6. 应用配置基线（`config.yaml`）

| 配置项 | 生产建议值 | 原因 |
|--------|-----------|------|
| `server.host` / `port` | `127.0.0.1` / `8080` | 管理面不直连业务网（离线 `install.sh` 默认 `0.0.0.0`，需收敛） |
| `server.mode` | `release` | 关闭 Gin 调试输出，避免路由/内部细节泄露 |
| `database.sslmode` | 同机 `disable`；跨机 `require`/`verify-full` | 防窃听 |
| `jwt.secret` | 随机 ≥32 字节，经环境变量注入 | 防伪造 token |
| `jwt.expire_seconds` | `7200`~`28800` | 缩短会话窗口 |
| `security.kek_path` | 独立目录 + 0600 | 私钥/密钥保护 |
| `security.report_dir` | 独立数据盘 + 0750 | 报告含业务信息 |
| `security.audit_hmac_key` | 显式配置（勿依赖 JWT 派生） | 审计链独立密钥，降低连带风险 |
| `report.max_size_bytes` | `52428800`（50MB）或更小 | 防上传 DoS |
| `report.gen_timeout_seconds` | `60`~`120` | 防 Chromium 挂死 |
| `k6.max_vus` | 按容量评估（默认 10000） | 防压测打爆被测系统与本机 |
| `k6.work_dir` | 独立目录 + 0750，独立磁盘 | 脚本/结果隔离 |
| `cleaner.low_priv_uid/gid` | 专用低权限账号 | 子进程降权 |
| `cleaner.allowed_host_ids` | 仅运维审批主机（逗号分隔 ID） | 空值=拒绝一切远程清理（安全默认） |
| `cleaner.allowed_script_hashes` | 审批脚本的 SHA256 | 防远程命令注入 |

## 7. 文件与上传

- 上传（报告导入）：扩展名白名单 + `http.DetectContentType` magic bytes 双校验 + 大小上限 + **随机文件名**，
  原文件名仅记录在摘要中（已 sanitize）。禁止把上传目录配置为可执行路径或 Web 根目录。
- 报告读取：路径来自 DB，`filepath.Clean` + 白名单目录前缀 + 符号链接解析校验；越界统一返回“文件不存在”。
- k6 脚本：`0600` 写入工作目录，执行结束立即删除（含执行期解密的认证头）。
- 前端静态资源：`go:embed` 只读内嵌，路径经 `fs.ValidPath` 校验，无目录列表。

## 8. 审计与日志

1. 用户日志 `hash = HMAC-SHA256(prev_hash || entry)` 链式签名；`user_log` 触发器禁止 UPDATE/DELETE；
   应用层只有查询接口。
2. 写操作审计覆盖：登录/登出/改密、管理员/角色变更、环境/产品/接口/阈值变更、任务执行/停止/清理、报告导入/导出等。
3. 日志写入前统一脱敏（`Authorization`、`password=`、私钥块），WebSocket 推送同样脱敏。
4. **保留与容量**：日志按 `created_at` **季度分区**。默认只预建 2026Q4 分区，
   **运维必须按季度提前建分区**，并按合规保留期导出/删除旧分区（应用不提供删除接口）：

```sql
CREATE TABLE user_log_2027q1 PARTITION OF user_log FOR VALUES FROM ('2027-01-01') TO ('2027-04-01');
CREATE TABLE system_log_2027q1 PARTITION OF system_log FOR VALUES FROM ('2027-01-01') TO ('2027-04-01');
CREATE TABLE test_log_2027q1  PARTITION OF test_log  FOR VALUES FROM ('2027-01-01') TO ('2027-04-01');
```

5. 建议将日志目录/DB 备份纳入集中审计存储；导出日志前再次脱敏。

## 9. 依赖与供应链

- 运行期外部依赖：PostgreSQL、k6、headless Chromium（离线包 `runtime/`、`bin/k6`）。
- 发布日期必须使用 `build-offline.sh --strict`，确保依赖齐全；包内 `manifest.yaml` 记录逐文件 SHA256，
  `install.sh`/`upgrade.sh` 部署前校验（篡改或夹带未登记文件即中止）。
- 建议：k6/Chromium/PostgreSQL 固定版本并记录来源；接入 SCA（`trivy fs`/`snyk`）与双引擎病毒扫描；
  禁止在包内携带抓包/调试/编译工具（`tcpdump`/`gdb`/`nmap`/`gcc`）。

## 10. 升级、备份与卸载

1. 升级：`upgrade.sh` 备份 → 停服 → 替换二进制 → `migrate up` → 健康检查 → 失败自动回滚。
   升级前确认已备份数据库与 `data/keys`。
2. 备份至少包含：PostgreSQL 数据、`/var/lib/auto_performance`（报告、KEK、配置）。
3. 卸载：默认保留数据；`--purge-data` 需输入 `YES` 二次确认后物理删除。
4. 迁移不可回退的场景（删列/改类型）必须先导出数据快照。

## 12. 已知残余风险与处置建议

| 编号 | 风险 | 影响 | 建议 |
|------|------|------|------|
| R-1 | 离线 `install.sh` 渲染 `server.host: 0.0.0.0` | 管理面可能直连业务网 | 部署后改为 `127.0.0.1`，或防火墙限制来源（`deploy/` 脚本本期未改） |
| R-2 | CORS 中间件返回 `*` | 分离部署时任意源可发起带 Bearer 的跨域请求（仍受 token 保护） | 同源部署；或在反代删除该头并配置受信源 |
| R-3 | `config.example.yaml` 含开发默认 JWT secret / DB 口令 | 误用默认值将导致 token 可伪造 | 安装脚本已生成随机值；禁止手工复制示例配置上线；发现默认值立即轮换 |
| R-4 | 登录锁定为进程内状态（单实例） | 多副本部署时锁定不共享 | 单实例部署；多副本需引入共享存储（Redis）或反代限流 |
| R-5 | 除登录外无通用接口限流 | 高频查询可能耗尽资源 | 反代层限流；关注 `/logs`、`/reports` 分页上限（已强制 ≤200） |
| R-6 | SSH 主机公钥需人工录入 | 录入错误将导致严格校验失败（失败关闭） | 通过受信渠道获取指纹，录入后先用 `ssh-keyscan` 核对 |
| R-7 | k6 压测流量可打过被测系统容量 | 影响被测业务 | 按环境评估 `max_vus`，压测窗口与业务方约定 |
| R-8 | 日志分区需运维手工预建 | 新季度写入失败 | 纳入季度运维任务/定时任务 |
