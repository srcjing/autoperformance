# ADR-0002：前端技术栈

- **状态**：已采纳（Accepted）
- **日期**：2026-10-26
- **决策者**：架构师
- **关联**：ADR-0001（后端）

## 背景

前端需要承载 6 大模块（环境/产品/测试/报告/日志/系统设置）的管理界面，特征为：

1. **重表格、重表单、重配置**：接口阈值配置、环境/标签、任务编排等以数据密集型交互为主。
2. **实时性强**：测试任务执行日志需要 WebSocket 实时刷新。
3. **在线报告查看**：需在线渲染 HTML / PDF 报告。
4. **离线部署**：前端构建产物需被后端 `go:embed` 内嵌，不允许运行时依赖外部 CDN。

## 备选方案

| 维度 | Vue3 + TS + Vite + Pinia + Router + shadcn-vue + Tailwind ✅ | Vue3 + Element Plus | React + Ant Design |
| --- | --- | --- | --- |
| 组件形态 | 源码进项目（无运行时依赖），完全掌控样式 | npm 依赖，主题定制有限 | npm 依赖 |
| 离线友好 | 极强（无 CDN、按需编译） | 强（本地打包） | 强 |
| 数据密集型组件（表格/表单/树） | 需自行组装（Table 基于 TanStack Table） | 开箱即用，非常全 | 开箱即用 |
| 样式定制 | Tailwind 原子化，定制成本低 | 主题变量定制，深度定制成本高 | 定制成本中 |
| 视觉差异化 | 高（不易撞脸） | 中（模板感强） | 中 |
| 学习/上手成本 | 中 | 低 | 低 |
| 与后端内嵌 | 构建产物标准静态资源 | 同 | 同 |

## 决策

**采用 Vue3 + TypeScript + Vite + Pinia + Vue Router + shadcn-vue + Tailwind CSS。**

- 图表：`ECharts`（`vue-echarts`）用于报告趋势/性能曲线。
- 表格：`TanStack Table`（`@tanstack/vue-table`）作为无头表格内核，配合 shadcn-vue 的 `Table` 封装。
- 代码/脚本编辑：`CodeMirror 6`（用于接口地址、压测脚本、模板 JSON 编辑）。
- JSON/结构化查看：`vue-json-pretty` 或自研 JsonViewer。
- 图标：`lucide-vue-next`（与 shadcn-vue 同源）。

## 理由

1. **离线部署友好**：shadcn-vue 采用"源码复制进项目"模式，组件实现随仓库管理，无运行时组件库依赖，无外部 CDN，天然契合内嵌部署与代码审计。
2. **视觉与定制可控**：Tailwind 原子化 + 组件源码在手，能精确匹配性能平台的专业视觉，避免"通用后台模板感"。
3. **工程化成熟**：Vite 构建快、产物可静态化；Pinia + Vue Router 官方维护，状态与路由方案稳定。
4. **实时性**：原生 WebSocket 集成简单，配合 Pinia 状态流即可实现日志/进度的实时推送渲染。

## 影响与取舍

- **影响**：数据密集型组件（高级表格、复杂表单）需基于 shadcn-vue + TanStack Table 自行组装，初期效率略低于 Element Plus 开箱即用；团队需熟悉 Tailwind。
- **取舍**：放弃 Element Plus 的"组件齐全度"。若后续出现大量重型管理组件（可编辑大表格、复杂级联、穿梭框）且交付压力大，可引入少量 Element Plus 组件作为补充（局部混用），但不作为默认组件体系。
- **可撤销条件**：若团队明确要求走千星/宙斯平台 QP 微前端体系，或需要与其他控制台系统深度集成，则切回 `QP + Vue + Qianxin Design` 体系。

## 结论

前端采用 **Vue3 + TypeScript + Vite + Pinia + Vue Router + shadcn-vue + Tailwind**，兼顾离线内嵌、视觉定制与工程化。
