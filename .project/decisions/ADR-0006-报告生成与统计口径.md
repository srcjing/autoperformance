# ADR-0006：报告生成与统计口径

- **状态**：已采纳（Accepted）
- **日期**：2026-10-26
- **决策者**：架构师
- **关联**：ADR-0001（后端）、ADR-0003（压测引擎）、`specs/architecture.md` §1.4 / §5.4

## 背景

需求方确认了两个此前悬而未决的口径问题，直接影响报告生成器与阈值评估器的实现：

1. 任务完成后报告以什么格式、什么策略生成？
2. 接口性能达标评估采用哪些指标、如何定义错误率？

## 决策

### 决策 A：报告默认全量生成 HTML + PDF + Word

- 任务完成后**默认全量生成 HTML + PDF + Word 三种格式**，一份报告三种产物并存。
- 任务创建时可**勾选调整**输出格式（例如仅 HTML，或 HTML + PDF）。
- 三种格式共用同一份数据源（结果摘要 + 阈值快照），保证视觉与结论一致。

### 决策 B：接口评估统计口径采用 P95 + P99 + 错误率

- 响应时间指标取 **P95 分位 + P99 分位**（不再以「平均响应时间」作为评估主口径，但平均响应时间仍可作为展示指标保留）。
- **错误率 = 失败请求数 / 总请求数**；非 2xx 响应或超时均计入失败请求。
- 阈值评估仍遵循「全阈值达标才算接口达标」，达标率 = 达标接口数 / 参与评估接口总数（见 PRD 第 9 章）。

## 理由

1. **全量生成满足离线与归档诉求**：平台面向离线部署，一次生成三格式可减少后续补生成，归档与离线读取都无需再依赖生成链路；任务创建时勾选则保留灵活性。
2. **分位指标比均值更能刻画长尾**：性能测试中均值易被长尾/抖动掩盖，P95/P99 更能反映真实用户体验；同时保留均值作为展示项，不丢失信息。
3. **错误率口径明确**：以「失败请求/总请求」统一口径，避免「成功率」「错误响应码判定」等口径歧义；超时显式计入失败，避免漏判无响应场景。

## 影响与取舍

- **影响**：报告生成器需同时产出 html/pdf/docx 三种产物并维护 `report_artifact` 记录；引擎适配层需在结果解析阶段计算 P95/P99 分位与错误率并归一化。
- **取舍**：全量生成带来一定生成耗时与存储开销，但换来离线归档的完整性；P95/P99 计算需保留完整样本（或流式分位估计），对内存有轻微影响。
- **可撤销条件**：若压测规模大且报告体积成为瓶颈，可将默认策略改为「按需生成」，但统计口径（P95/P99 + 错误率）建议长期保持稳定以维持历史报告可比性。

## 结论

报告默认全量生成 **HTML + PDF + Word**（任务创建时可勾选调整）；接口评估统计口径采用 **P95 + P99 分位响应时间 + 错误率（失败请求/总请求）**。
