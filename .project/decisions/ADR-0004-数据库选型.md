# ADR-0004：数据库选型

- **状态**：已采纳（Accepted）
- **日期**：2026-10-26
- **决策者**：架构师
- **关联**：ADR-0001（后端）

## 背景

平台需要持久化的数据包括：

1. **结构化元数据**：环境、标签、产品、接口、阈值、测试模板、测试任务、管理员、证书、SSH-Host。
2. **半结构化/动态数据**：接口阈值配置（字段可能随接口类型扩展）、报告元数据与指标快照（metrics JSON）、k6 结果摘要。
3. **日志**：用户日志、系统日志、测试日志（量大、时序性强）。
4. **文件产物**：报告 HTML/PDF/Word、证书文件、SSH 密钥（存文件系统，DB 存路径与元信息）。

## 备选方案

| 维度 | PostgreSQL ✅ 推荐 | MySQL | SQLite（嵌入式） |
| --- | --- | --- | --- |
| 半结构化 | JSONB（可索引、可查询） | JSON（功能弱） | JSON（功能弱） |
| 事务/一致性 | 强（MVCC） | 强（InnoDB） | 单写，并发弱 |
| 离线部署 | 成熟（离线包/镜像） | 成熟 | 极强（单文件） |
| 扩展/生态 | 强（pgvector 等可选） | 强 | 弱 |
| 运维面 | 中 | 中 | 极低 |
| 并发写入（日志/任务） | 强 | 强 | 弱 |

## 决策

**主库采用 PostgreSQL；日志采用 PostgreSQL 表 + 分区（按时间）+ 归档策略；文件产物存本地对象存储目录（文件系统），DB 仅存路径与元数据。**

- 驱动：`pgx`（原生，高性能）或 `gorm` 的 postgres 方言（与 ADR-0001 的 ORM 决策一致，最终以实现便捷性定）。
- 迁移：`golang-migrate`，随升级脚本执行。
- 阈值/报告指标：使用 `JSONB` 列存储接口阈值配置、指标快照、k6 结果摘要，便于按需扩展字段而不频繁改表。

## 理由

1. **JSONB 契合业务**：接口阈值、指标快照、报告元数据本质是半结构化数据，PostgreSQL 的 JSONB 可建索引、可查询、可原位扩展，显著降低表结构变更频率，提升可维护性。
2. **离线部署成熟**：PostgreSQL 有稳定的离线安装包与 Docker 镜像，可随部署包分发，满足强约束。
3. **一致性与并发**：测试任务状态流转、日志高并发写入需要可靠事务与并发控制，PostgreSQL 的 MVCC 表现优于嵌入式库。
4. **可移植**：开源、跨平台（linux/amd64、arm64），许可宽松（PostgreSQL License），无商业授权风险。

## 影响与取舍

- **影响**：相比嵌入式 SQLite，需额外运维一个数据库实例；相比 MySQL，需团队熟悉 PostgreSQL 生态。
- **取舍**：放弃 SQLite 的"零运维单文件"。若未来出现"纯单机、无 DBA、安装包要最小"的轻量交付形态，可引入 SQLite 作为"轻量模式"（通过 repository 抽象切换），但默认生产形态仍为 PostgreSQL。
- **可撤销条件**：若团队/客户环境统一使用 MySQL 且无 JSONB 强需求，可切 MySQL（JSON 能力降级，需用关联表表达阈值/指标）。

## 结论

数据库采用 **PostgreSQL**，用 JSONB 承载阈值/指标等半结构化数据，日志分区归档，文件产物外置文件系统。
