# ADR-0005：权限模型（分级分权 RBAC）

- **状态**：已采纳（Accepted）
- **日期**：2026-10-26
- **决策者**：架构师
- **关联**：ADR-0001（后端）、ADR-0004（数据库）、`specs/architecture.md` §5.3、`specs/frontend-structure.md` §6

## 背景

平台最初的权限设想是「固定角色枚举」（超级管理员 / 测试管理员 / 只读用户），但需求方在多轮确认后明确：管理员职责差异大，固定角色无法覆盖「只读观察员」「测试操作员」「仅管理证书的运维」等灵活形态。需要一种**不预设角色枚举**、可随组织自行组合的授权模型。

## 备选方案

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 固定角色（ACL） | 预置 3 个角色，代码里硬编码角色 → 能力映射 | 实现简单，但每新增一种职责组合就要改代码/发版，扩展性差 |
| 资源级 RBAC | 按「对象 + 动作」授权（如 `interface:read`） | 粒度细但配置量大，与「子模块」粒度的产品诉求错位 |
| 子模块级分级分权 RBAC ✅ | 权限粒度到子模块，每个子模块授予只读/可写，角色 = 子模块授权项集合 | 与 PRD 第 8 章一致，既可控又不过度细碎，支持灵活组合 |

## 决策

**采用「分级分权 RBAC」：权限粒度到子模块级，每个子模块独立授予「只读（read）/ 可写（write）」；管理员通过「角色」获得权限，角色是子模块授权项的集合，管理员最终权限 = 所授角色权限范围的并集。**

- **权限粒度**：子模块级（如「环境管理 · 环境列表」「系统设置 · 证书管理」），每项只读/可写。
- **角色（Role）实体**：角色 = 权限范围集合，支持新建/删除/修改；被管理员引用时禁止删除。
- **管理员 ↔ 角色 多对多**：管理员可授多个角色，最终权限为并集。
- **管理员字段**：用户名（登录名）、姓名、手机号、邮箱、描述 + 角色授权。
- **内置 admin**：系统默认内置 `admin`，初始密码 `Cqmyg@123`，默认拥有全部子模块可写权限；首次登录强制修改密码，不可删除/停用。

### 数据模型（4 张表）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `admin` | id, username(唯一), name, phone, email, description, password_hash, status, last_login_at, deleted_at | 管理员账号 |
| `role` | id, name(唯一), description, deleted_at | 角色 = 权限范围集合 |
| `role_permission` | id, role_id, module_code, permission(read/write) | 子模块级授权项 |
| `admin_role` | admin_id, role_id | 管理员 ↔ 角色 多对多 |

子模块授权码（module_code）：`env.list` / `env.tag` / `product.list` / `product.interface` / `testing.task` / `testing.template` / `report.list` / `log.user` / `log.system` / `log.test` / `setting.admin` / `setting.cert` / `setting.ssh`。

## 理由

1. **契合组织灵活授权诉求**：不预设角色枚举，运维可自行组合出「只读观察员」「测试操作员」等形态，无需改代码。
2. **粒度适中**：子模块级比对象级配置成本低，又比模块级更能精确隔离敏感功能（管理员/证书/SSH 可单独收紧为「可写且仅授予少数人」）。
3. **简单可维护**：权限 = 授权项并集的集合包含判断，后端中间件与前端指令/守卫实现直接，无复杂策略引擎。

## 影响与取舍

- **影响**：需要新增 `role` / `role_permission` / `admin_role` 三张表与相应 CRUD 接口；前端需实现权限矩阵编辑器与按钮级权限指令；登录后需拉取并缓存管理员权限集合。
- **取舍**：放弃固定角色枚举的「零配置」简单性，换来授权灵活性；权限不写入 JWT（从 DB 实时/短 TTL 缓存读取），换取角色变更即时生效。
- **可撤销条件**：若后续业务确认只需极少数固定角色且无动态授权诉求，可降级为固定角色 + 权限映射表。

## 结论

权限模型采用**分级分权 RBAC**：子模块级只读/可写，角色作为权限范围集合，管理员多角色并集授权，内置 `admin` 默认全权限。
